# Export Primary Fields + Runtime Terrain Derivation

## Why

The baked `terrain-colors.png` freezes every climate decision (latitude effect, sea level, rainfall) at generation time, and the baked `map.bin` magnitude bits are not real bathymetry — so the shell/simulator cannot faithfully re-render terrain as its live systems (seasonal temperature, later weather and water) change the world. The WESL worldgen pipeline can already derive ocean, climate, drainage, biomes, and the exact terrain colors on the GPU in under a second — the only missing input is the primary field it starts from: full-precision elevation, plus the generation config. Exporting those turns bake-time climate knobs into runtime scalars.

## What Changes

- Every baked map ships a third sidecar, `elevation.bin`: the full-precision elevation plane (u16, row-major, 2 bytes/tile), exported by the generator alongside `terrain-colors.png` and `layers.bin`.
- The map manifest records the world-engine render config (seed, seaLevel, latitudeEffect, and the other `FoundationWorldEngineMapConfig` knobs) so the derivation pipeline is reproducible per map.
- Maps whose engine state is gone (earth, earthxl, earthmini, spqr, world, majormenor) get `elevation.bin` retrofitted via `derive-layers.ts`, same as their existing sidecar retrofit.
- The Go baker passes `elevation.bin` through with a size check (copy-only, never parsed), mirroring `layers.bin` handling; `gen-maps` regenerates all map folders.
- Loaders (`MapData`, `FetchGameMapLoader`, manifest schema) expose the new sidecar; `MapConsistency.test.ts` enforces its presence and size for every map.
- The shell derives terrain at map load: elevation + config → the existing WESL worldgen passes (ocean flood, climate, depression fill, flow, irrigation, biome) → live color pass as the terrain view. Climate knobs (`latitudeEffect`, `elevationCooling`, `rainNoise`, seasonal tilt/phase) become tunable runtime scalars in the shell.
- `terrain-colors.png` is unchanged and remains the in-game renderer's base texture and the shell's fallback; this change adds a parallel runtime path, it does not remove the baked one.

## Capabilities

### New Capabilities

- `elevation-sidecar`: the `elevation.bin` format, export, retrofit, baking, loading, and consistency guarantees — every map ships a full-precision primary elevation plane plus its render config.
- `runtime-terrain-derivation`: the shell derives ocean/climate/drainage/biome layers and live terrain colors from the elevation sidecar and config at map load, with climate parameters adjustable at runtime.

## Impact

- `src/games/alternative/world/GeneratorMapExport.ts` — export `elevation.bin` (new encoder, single source of truth for the format, like `MapLayers.ts` is for `layers.bin`).
- New `src/core/game/ElevationMap.ts` (or extension of `MapLayers.ts`) — format constants, encode/decode, size validation shared by exporter, loaders, and tests.
- `map-generator/map_generator.go` — copy + size-check passthrough for `elevation.bin`; manifest gains the render config block.
- `map-generator/derive-layers.ts` — retrofit path writes `elevation.bin` for image-only maps.
- `src/core/game/GameMapLoader.ts` / `FetchGameMapLoader.ts` — `MapData.elevationBin`.
- `tests/MapConsistency.test.ts` — new sidecar present + size-consistent for every map in `resources/maps/`.
- `src/client/GameShellPage.ts` + `src/client/webgpu/` — load-time derivation (headless worldgen passes on the shared device) and the live color view; shell-only, no game-rule changes.
- `resources/maps/*` — regenerated by `npm run gen-maps` after exporter/baker changes.
